## Как читать этот документ

Документ — **конспект проверенного, а не источник истины**. Справка Tilda меняется, платформа развивается; конспект месячной давности может увести в неверное решение.

**Прецедент 17.08.2026:** по этому документу была дана оценка, что параллельные входы в каталог (по культуре, вредному объекту, ДВ) потребуют 190–310 страниц ручной сборки. Сверка со справкой Tilda в тот же день показала, что механика разделов каталога закрывает бо́льшую часть задачи автоматически — в конспекте про это не было ни строки. Оценка была пессимистичной вдвое-втрое.

**Правило:** платформенное решение принимается только после сверки со справкой (`help-ru.tilda.cc`). Этот документ говорит, что уже сверяли и когда.

## 2. Домены и структура сайта

- **1 сайт = 1 домен.** Мультидоменность (региональные поддомены с разным контентом на одном сайте) невозможна без разделения на несколько сайтов в аккаунте.
- **URL по умолчанию:** `/page12345678/`. ✅ *(сверено 17.08.2026)* ЧПУ настраивается вручную для каждой страницы — массовой генерации адресов из заголовка нет. Это же ограничение называется в отраслевых обзорах 2026 г. одной из типовых причин ухода с платформы при росте числа страниц.
- **Файл `.htaccess` недоступен.** Тонкая маршрутизация, серверные редиректы, кастомные заголовки — только через панель настроек Tilda.
- **301-редиректы** настраиваются в панели, но с ограничениями (нет regex-правил массовой миграции URL).
- **Мультиязычность** реализуется через отдельные страницы с языковыми суффиксами в URL — единого механизма i18n нет.

💡 **Для проекта:** мультиязычность не требуется. Массовая миграция URL со старого сайта — **ОВ16** (в план редиректов включены страницы `/s/` старого сайта, в том числе 301 с «Гербицидов промышленных» на подраздел по ДМ31).

## 3. HTML / CSS / JavaScript — кастомный код

**Что можно:**
- Вставлять произвольный HTML/CSS/JS через блок `T123` (HTML-код).
- Внутри Zero Block добавлять HTML-элементы.
- Добавлять CSS/JS в `<head>` и перед `</body>` через настройки сайта.
- Использовать модификации сообщества (Nolim, TiCode, dabreeze и др.) для расширения функционала стандартных блоков.

**Чего нельзя:**
- **Нет доступа к серверной стороне.** Никакого PHP/Python/Node — только клиентский JS.
- **Нельзя редактировать HTML стандартных блоков напрямую** — только через CSS-переопределение классов или JS-модификацию DOM.
- **Скрипты в кастомных блоках выполняются после загрузки страницы**, что осложняет работу с первым рендером.
- **Автоматическое кэширование** может конфликтовать с кастомными скриптами — требуется тестирование после каждой публикации.

💡 **Для проекта:**
- Макеты от Claude Design (главная, листинг, карточка) реализуются в Zero Block без критических проблем.
- Модал «Получить консультацию» (ДМ21) — штатный попап + кастомный CSS; conversational-формат (по одному вопросу на экран) потребует JS.
- Калькулятор нормы расхода (ОВ17) — только клиентский JS.

## 4. Zero Block (визуальный редактор кастомных блоков)

- **Ограничение на количество элементов:** практически — до 30 копий из буфера, до ~300 блоков на странице (по опыту сообщества, официального лимита нет; при превышении редактор тормозит).
- **Адаптив настраивается на 5 брейкпоинтов** (1200 / 960 / 640 / 480 / 320 px). Промежуточные разрешения интерполируются автоматически, иногда непредсказуемо.
- **Нет CSS Grid и flex-контейнеров нативно** — вёрстка через абсолютное позиционирование. Auto-layout частично закрывает проблему.
- **Копирование Zero Block между сайтами** работает, между аккаунтами — через экспорт JSON.

💡 **Для проекта:** все макеты свёрстаны под те же 5 брейкпоинтов, что и в Zero Block, — переносятся без пересчёта сетки. Особое внимание при сборке: sticky CTA карточки (до 640 px), горизонтально прокручиваемая таблица регламента, аккордеоны.

## 5. Каталог товаров (Магазин 2.0)

**Возможности:**
- До 50 000 товаров на тарифе Business, разделы и подразделы.
- Импорт/экспорт CSV, экспорт YML (Яндекс.Маркет).
- Свойства товара (характеристики, варианты, доп. опции).
- Фильтры по свойствам, поиск, сортировка (по цене, алфавиту, новизне).
- Блоки каталога: ST300, ST305N, ST310N, ST315N, ST320N, ST340.
- Отдельная страница товара (не попап) — включается в настройках блока.

**Ограничения:**
- **Только одна корзина на страницу.** 💡 Для проекта неактуально — витрина без корзины (У01).
- **Ограниченная кастомизация карточки товара** в стандартных блоках — точная композиция достигается через Zero Block + модификацию NLM151 (Nolim) или аналог.
- **Шаблон страницы товара един для всего каталога** — разные шаблоны для разных категорий средствами платформы не сделать.
  💡 **Принято для проекта (09.08.2026):** единый шаблон карточки для всех 7 категорий — Гербициды, Инсектициды, Фунгициды, Протравители, Стимуляторы роста, Адьюванты, Десиканты. Схема полей A–H (`catalog-ia-v1.md` §4) одинаково применима ко всем; различаются значения, а не структура.
  *(Исправлено 17.08.2026: в первой редакции список категорий был указан неверно — фигурировали «Родентициды» и «Регуляторы роста», которых в каталоге нет.)*
- **Сортировка «по популярности»** нативно не работает — нужна JS-модификация с подсчётом просмотров или ручное поле в свойствах товара (**ОВ13**; дефолт до закрытия — «А-Я»).
- **Массовая генерация метатегов для товаров отсутствует** — title/description каждой карточки заполняются вручную либо через API/скрипт.
- **Нет админки товара с историей изменений** — правки сохраняются без ревизий.

### 5.1 Разделы и подразделы каталога ✅ *(сверено 17.08.2026 по справке «Создание категорий для товаров»)*

Ключевой механизм для параллельных входов (ДМ02, ДМ26). Что подтверждено справкой:

| Возможность | Значение для проекта |
|---|---|
| **Товар может принадлежать нескольким разделам и подразделам одновременно** | Один препарат попадает и в «Гербициды», и в «Пшеница», и в «Глифосат» — параллельные входы не требуют дублирования товаров |
| **До 10 уровней вложенности подразделов** | Хватает на схему «По культуре → Пшеница» и любую разумную иерархию |
| **Массовое назначение разделов:** выделить товары → выбрать действие и раздел | Назначение культур и объектов 87 препаратам — не поштучная работа |
| **Разделы задаются при импорте CSV** | Файл импорта генерируется скриптом из готовых маппингов `product-crop-mapping-v1.md` и `product-pest-mapping-v1.md` |
| **У раздела есть поля названия и описания;** блок ST340 умеет динамически подставлять их на страницу | Заголовки и лиды страниц входов не пишутся по одной |
| **Разделу можно задать страницу с товарами** (дополнительные настройки) | Управляемая привязка раздела к странице вывода |
| **Раздел можно скрыть из фильтров и навигации** (галочка) | Пригодится для служебных разделов, не предназначенных посетителю |
| **Главная страница каталога** задаётся в настройках и становится родительским адресом для всех разделов | Базовый адрес каталога управляем |
| **Товар не наследует раздел автоматически из подраздела** | При выводе раздела верхнего уровня товары из подразделов нужно добавлять в него дополнительно — учесть в скрипте генерации импорта |

**Чего справка не даёт — проверяется на практике** ⚠️:

1. **Какой URL получает страница раздела** — читаемый (`/catalog/kultura/pshenitsa/`) или служебный. От этого зависит, нужны ли ручные посадочные.
2. **Можно ли задать разделу свой slug.**
3. **Есть ли у раздела собственные мета-теги** или они наследуются от страницы вывода.
4. **Дубли:** товар в нескольких разделах — сколько адресов у карточки, ставится ли canonical.
5. **Хлебные крошки при мультипринадлежности** — какой путь показывается.

📌 **Задача на проверку:** `phase-5-tilda/task-catalog-sections-test.md` — чек-лист из 15 пунктов, требует доступа к аккаунту Tilda. Блокирует **ОВ36** (объём ЧПУ-страниц параллельных входов) и оценку Phase 5. Вилка в оценке — между ~105 и ~400 страницами.

💡 **Для проекта:**
- Схема данных карточки (поля A–H) реализуется через штатные свойства товаров + описание.
- **Карточки товаров не создаются как отдельные страницы** — выводятся через единый шаблон из каталога. 87 карточек — это импорт CSV, а не 87 страниц ручной сборки.
- Обзорные страницы серий (ПИ06) — отдельные страницы, не карточки; не привязаны к движку каталога.
- Кросс-селл по алгоритму слотов (ДМ29) — ручная привязка «Похожие товары» либо JS-модификация; матрица на 87 SKU готовится отдельно.

## 6. SEO

**Что доступно:**
- Ручные title, description, OG-теги для каждой страницы.
- ЧПУ — вручную по каждой странице.
- Хлебные крошки (BreadcrumbList) — через блоки или ручную вставку JSON-LD.
- Микроразметка Product, Organization, WebSite, ItemList/CollectionPage (ДМ33) — через JSON-LD в `<head>`.
- Автогенерация `sitemap.xml`.
- Подключение Яндекс.Вебмастер, Google Search Console, Метрики, GA4.

**Что ограничено:**
- **`robots.txt` — только частичное редактирование.** Добавить disallow можно, переписать файл целиком или удалить системные правила — нет.
- **`sitemap.xml` не редактируется вручную.** Порядок, приоритет, changefreq задаются платформой.
- **Нет массовой генерации метатегов** по шаблону («{название} — купить в Челябинске»). Для каталога — ручная работа или скрипт через API.
- **`meta robots`** доступен на уровне страницы, но не для отдельных URL с параметрами (фильтры каталога).
- **Canonical** ставится автоматически на основной URL, ручная настройка ограничена.
- **Нет автоматической перелинковки** — внутренние ссылки простраиваются руками. 💡 В проекте это закрыто заранее: блок «Область применения» на карточке (ссылки на культуры и объекты), кросс-селл (ДМ29), «Похожие подборки» на листинге (ДМ32), хлебные крошки.

💡 **Для проекта:** SEO-возможностей достаточно для локального продвижения по коммерческим запросам в Челябинске и области. Массовое проставление метатегов карточек — Phase 4/5, скриптом при подготовке CSV.

## 7. Формы и приём данных

- **Формы принимаются в:** Tilda «Заявки» (встроенная), email, Google Sheets, Notion, AmoCRM, Bitrix24, RetailCRM, Мой Склад, MailChimp, Unisender, SendGrid, Telegram, MAX, VK, Webhook.
- **Один Webhook на форму.** Разделение вебхуков по формам на одной странице — через отдельные страницы.
- **На Free-тарифе формы работают 30 дней** после отключения подписки, затем перестают.
- **Валидация полей** базовая (обязательное, email/tel). Условная логика (показывать поле B, если выбрано A) — кастомный JS.
- **Загрузка файлов через форму** — до 10 МБ на файл.
- **Капча** — reCAPTCHA v2 штатно.

💡 **Для проекта:** стек уведомлений ДМ04 (Тильда «Заявки» + Telegram Business + MAX + Google Sheet) реализуется штатными интеграциями — внешняя CRM не нужна (НР11). Система форм ДМ30 и conversational-модал ДМ21 укладываются в штатный функционал; пошаговый формат — через JS.

## 8. Изображения и медиа

- **Максимальный вес изображения:** 5 МБ.
- **Автоуменьшение до 1680 px** по большой стороне при загрузке.

- **CDN Tilda** используется автоматически.
- **Видео:** только встраивание (YouTube, Vimeo).

💡 **Для проекта:** фото упаковки (ДМ28, два ракурса на карточку) — в пределах лимитов. Скан дилерского письма — PDF или JPG до 5 МБ. Иконки культур (когда появится система иконок) — SVG.

## 9. Скорость загрузки

- **Нет доступа к серверным настройкам:** gzip, brotli, кастомный HTTP-кэш, edge-функции недоступны.
- **Автосжатие изображений** работает не всегда оптимально — критичные изображения оптимизировать до загрузки.
- **Скрипты сторонних сервисов** увеличивают время загрузки.
- **PageSpeed:** ⚠️ обычно 70–90 на десктопе, 40–70 на мобильных — сильно зависит от количества Zero Block с анимациями.
- **CDN Tilda** обеспечивает базовую скорость по России.

💡 **Для проекта:** целевой PageSpeed — не хуже 60 (mobile) / 85 (desktop). После сборки — оптимизация изображений и аудит скорости. Карточка товара тяжелее среднего: фото, таблица регламента, аккордеоны, кросс-селл с четырьмя фото.

## 13. Что важно помнить при проектировании

1. **Массовые операции с товарами** (метатеги, привязки) — скрипт при подготовке CSV или ручной труд. Планировать трудозатраты.
2. **`robots.txt` и `sitemap.xml`** — базовая генерация, тонких настроек нет.
3. **Redirect-план миграции URL** — обязательный артефакт перед запуском (**ОВ16**).
4. **Никакой серверной логики** — динамика только через клиентский JS или внешние сервисы.
5. **Разделы каталога — главный рычаг** для параллельных входов; до проверки задачи по §5.1 объём Phase 5 оценивается вилкой.
6. **Ссылка в макете — только на страницу с записью в реестре** (правило введено 17.08.2026 после находок «Полезное» и «Оптовым покупателям»; см. `00-management/site-pages-inventory.md`).
