# Ограничения платформы Tilda

**Проект:** Редизайн сайта ООО «Восток-Агрохим»
**Дата составления:** 09.08.2026
**Статус:** живой документ, обновляется при выявлении новых ограничений в ходе проектирования
**Назначение:** зафиксировать рамки платформы, чтобы решения по IA, дизайну и функциональности не упирались в непреодолимые лимиты на этапе реализации. Каждое ограничение сопровождается пометкой о влиянии на текущий проект и, где применимо, обходом.

## 2. Домены и структура сайта

- **1 сайт = 1 домен.** Мультидоменность (например, региональные поддомены с разным контентом на одном сайте) невозможна без разделения на несколько сайтов в аккаунте.
- **URL по умолчанию:** `/page12345678/`. ЧПУ настраивается вручную для каждой страницы (нет массовой генерации из title).
- **Файл `.htaccess` недоступен.** Тонкая маршрутизация, серверные редиректы, кастомные заголовки — только через панель настроек Tilda.
- **301-редиректы** настраиваются в панели, но с ограничениями (нет regex-правил массовой миграции URL).
- **Мультиязычность** реализуется через отдельные страницы с языковыми суффиксами в URL — единого механизма i18n нет.

**Для проекта:** мультиязычность не требуется. Массовая миграция URL со старого сайта на новый — открытый вопрос, вынесен в основной реестр как **ОВ16** (после аудита старого сайта).

## 3. HTML / CSS / JavaScript — кастомный код

**Что можно:**
- Вставлять произвольный HTML/CSS/JS через блок `T123` (HTML-код).
- Внутри Zero Block добавлять HTML-элементы.
- Добавлять CSS/JS в `<head>` и перед `</body>` через настройки сайта.
- Использовать модификации сообщества (Nolim, TiCode, dabreeze и др.) для расширения функционала стандартных блоков.

**Чего нельзя:**
- **Нет доступа к серверной стороне.** Никакого PHP/Python/Node — только клиентский JS.
- **Нельзя редактировать HTML стандартных блоков напрямую** — только через CSS-переопределение классов или JS-модификацию DOM.
- **Скрипты в кастомных блоках выполняются после загрузки страницы**, что осложняет SSR-логику и работу с первым рендером.
- **Автоматическое кэширование** может конфликтовать с кастомными скриптами — требуется тестирование после каждой публикации.

**Для проекта:**
- Дизайн главной, свёрстанный в Zero Block по макету от Claude Design, реализуется без критических проблем.
- Модальная форма «Получить консультацию» (ДМ21) — реализуется через стандартный попап Tilda + кастомный CSS.
- Логика вычислений в форме (например, расчёт по нормам расхода) — только клиентский JS.

## 4. Zero Block (визуальный редактор кастомных блоков)

- **Ограничение на количество элементов в одном Zero Block:** практически рекомендуется до 30 копий из буфера, до ~300 блоков на странице (по опыту сообщества, официального лимита нет, но при превышении редактор тормозит).
- **Адаптив настраивается на 5 брейкпоинтов** (1200 / 960 / 640 / 480 / 320 px). Промежуточные разрешения интерполируются автоматически, что иногда даёт непредсказуемый результат.
- **Нет CSS Grid и flex-контейнеров нативно** — верстка через абсолютное позиционирование внутри Zero Block. Auto-layout (появился в 2024) частично закрывает эту проблему, но не полностью.
- **Копирование Zero Block между сайтами** работает, между аккаунтами — только через экспорт JSON.

**Для проекта:** блоки главной, свёрстанные в Zero Block, должны пройти тест на всех 5 брейкпоинтах перед сдачей. Особое внимание — блоку «Каталог» и блоку «Как мы работаем» с иконками.

## 5. Каталог товаров (Магазин 2.0)

**Возможности:**
- До 50 000 товаров на тарифе Business, категории и подкатегории.
- Импорт/экспорт CSV, экспорт YML (Яндекс.Маркет).
- Свойства товара (характеристики, цвет, размер и т.п.) + варианты + доп. опции с изменением цены.
- Фильтры по свойствам, поиск, сортировка (по цене, алфавиту, новизне).
- Блоки каталога: ST300, ST305N, ST310N, ST315N, ST320N.
- Отдельная страница товара (не попап) — включается в настройках блока.

**Ограничения:**
- **Только одна корзина на страницу.** Несколько независимых корзин (например, оптовая и розничная на одной странице) — нельзя без модификаций. **Для проекта неактуально** (закрыто 09.08.2026 — сайт работает как витрина, корзина/избранное не предусматривались, см. У01).
- **Ограниченная кастомизация карточки товара** в стандартных блоках — точная композиция достигается только через Zero Block + модификацию NLM151 (Nolim) или аналог.
- **Шаблон страницы товара един для всего каталога** — разные шаблоны для разных категорий средствами платформы не сделать. **Принято для проекта:** единый шаблон карточки товара для всех 7 категорий (Гербициды, Инсектициды, Фунгициды, Протравители, Родентициды, Регуляторы роста, Десиканты). Обоснование — схема полей A–H (см. `catalog-ia-v1.md`) одинаково применима ко всем категориям; различия только в значениях полей (норма расхода, объекты, культуры), а не в структуре. Принято 09.08.2026.
- **Сортировка «по популярности»** нативно не работает — требуется JS-модификация с подсчётом просмотров или ручное поле в свойствах товара (см. **ОВ13** в основном реестре).
- **Массовая генерация метатегов для товаров отсутствует** — title/description каждой карточки заполняются вручную (либо через API/скрипт).
- **Нет полноценной админки товара с историей изменений** — все правки сохраняются, но без ревизий.

**Для проекта:**
- Card data schema (поля A–H из `catalog-ia-v1.md`) реализуема через штатные свойства товаров + описание.
- Overview-страницы для брендовых серий (§6.6) — это отдельные страницы, не карточки товаров; они не привязаны к движку каталога и легко реализуются.
- Кросс-селл с приоритетом серии — потребует либо ручной привязки «Похожие товары», либо JS-модификации.

## 6. SEO

**Что доступно:**
- Ручные title, description, OG-теги для каждой страницы.
- ЧПУ (человекопонятные URL) — вручную по каждой странице.
- Хлебные крошки (микроразметка BreadcrumbList) — через специальные блоки или ручную вставку JSON-LD.
- Микроразметка Product, Organization, WebSite — через вставку JSON-LD в `<head>` страницы.
- Автогенерация `sitemap.xml`.
- Подключение Яндекс.Вебмастер, Google Search Console, Метрики, GA4.

**Что ограничено:**
- **`robots.txt` — только частичное редактирование.** Панель Tilda позволяет добавить disallow-директивы, но полностью переписать файл или удалить системные правила платформы нельзя.
- **`sitemap.xml` не редактируется вручную.** Порядок, приоритет, changefreq задаются платформой. Для добавления сторонних URL — только через отдельный кастомный XML.
- **Нет массовой генерации метатегов** по шаблону (например, «{название} — купить в Челябинске»). Для каталога с десятками товаров это ручная работа.
- **`meta robots` (noindex, nofollow)** — доступен на уровне страницы, но не на уровне отдельных URL с параметрами (например, фильтры каталога).
- **Canonical** ставится автоматически на основной URL страницы, ручная настройка ограничена.

**Для проекта:** SEO-возможностей достаточно для локального продвижения по коммерческим запросам в Челябинске и области. Массовое проставление метатегов для карточек товаров — задача Phase 4 (ОВ10 частично) или ручной труд для контент-менеджера клиента после запуска.

## 7. Формы и приём данных

- **Формы принимаются в:** Tilda CRM (встроенная), email, Google Sheets, Notion, AmoCRM, Bitrix24, RetailCRM, Мой Склад, MailChimp, Unisender, SendGrid, Telegram, VK, Webhook (произвольный URL).
- **Один Webhook на форму** — простая настройка. Разделение вебхуков по разным формам на одной странице — через отдельные страницы.
- **На Free-тарифе формы работают 30 дней после отключения подписки**, затем перестают.
- **Валидация полей** — базовая (обязательное поле, тип email/tel). Условная логика (показывать поле B, если выбрано A) — только через кастомный JS.
- **Загрузка файлов через форму** — до 10 МБ на файл, ограничение по совокупному размеру задаётся типом хранилища.
- **Капча** — reCAPTCHA v2 подключается штатно.

**Для проекта:** «Получить консультацию» (ДМ21) — стандартный попап с 3–4 полями, подключаемый к любой CRM клиента (либо к внутренней Tilda CRM с email-уведомлением). Никаких ограничений.

## 8. Изображения и медиа

- **Максимальный вес изображения:** 5 МБ.
- **Автоматическое уменьшение до 1680 px** по большой стороне при загрузке.
- **Форматы:** JPG, PNG, GIF, SVG, WEBP (через HTML-элемент).
- **Автоматическая генерация WebP** для современных браузеров — работает по умолчанию.
- **Lazy load** включён по умолчанию (может конфликтовать с некоторыми модификациями).
- **CDN Tilda** используется автоматически. Замена на сторонний CDN — только для экспорт-версии сайта.
- **Видео:** только через встраивание (YouTube, Vimeo). Прямая загрузка видео на Tilda ограничена — рекомендуется внешний хостинг.

**Для проекта:** SVG-канистры и иконки в блоках 4 и 5 — без ограничений. Скан-дилерского письма от «Август» — PDF или JPG до 5 МБ, вставляется как файл или через блок с превью.

## 9. Скорость загрузки

- **Нет доступа к серверным настройкам:** gzip, brotli, кастомный HTTP-кэш, edge-функции — недоступны.
- **Автосжатие изображений** — работает, но не всегда оптимально; критичные изображения желательно оптимизировать до загрузки (TinyPNG, Squoosh).
- **Скрипты сторонних сервисов** (Метрика, GA4, чаты, виджеты) увеличивают время загрузки — рекомендуется минимизировать.
- **PageSpeed на десктопе:** обычно 70–90 из коробки. На мобильных — 40–70, сильно зависит от количества Zero Block с анимациями.
- **CDN Tilda** обеспечивает базовую скорость по России.

**Для проекта:** ожидается, что главная будет тяжелее среднего лендинга из-за 7 блоков с иллюстрациями и Zero Block-версткой. Целевой PageSpeed — не хуже 60 (mobile) / 85 (desktop). После сдачи макета — обязательная оптимизация изображений и аудит скорости.

## 10. Шрифты

- **Максимум 3 шрифта на сайт.**
- **Источники:** встроенная библиотека Tilda (базируется на Google Fonts), собственная загрузка WOFF/WOFF2, Google Fonts, Adobe Fonts.
- **Все начертания одного шрифта считаются отдельными файлами** и влияют на скорость загрузки.

**Для проекта:** дизайн-направление «Уверенная классика» использует пару Merriweather (заголовки) + Inter или Manrope (текст) — это 2 шрифта, что укладывается в лимит. Третий слот остаётся резервным.

## 11. Экспорт и миграция

- **Экспорт HTML/CSS/JS** доступен на тарифах Business+ — можно скачать статичный архив сайта и разместить на любом хостинге.
- **Экспорт каталога:** CSV (все товары), YML (для Яндекс.Маркета).
- **Экспорт форм/лидов:** CSV из Tilda CRM.
- **Экспорт настроек сайта:** нет полноценного JSON-бэкапа проекта. Только копирование страниц внутри Tilda.
- **Обратная миграция** (импорт с других CMS) — только вручную, страницу за страницей.

**Для проекта:** экспорт HTML — резерв на случай ухода с платформы. Регулярный экспорт CSV каталога — рекомендуемая практика после запуска.

## 12. Аналитика и трекинг

- Штатная интеграция с Яндекс.Метрикой, Google Analytics 4, VK Пикселем, Facebook Pixel, Google Tag Manager.
- События электронной коммерции (просмотр товара, добавление в корзину, покупка) отправляются в Метрику/GA4 автоматически.
- Кастомные события — через `dataLayer.push` в кастомном JS.

**Для проекта:** цели «отправка формы «Получить консультацию»» и «клик по телефону» — настраиваются в Метрике штатно.

## 13. Что важно помнить при проектировании

1. **Одна корзина на страницу** — для проекта неактуально (У01, витрина без корзины).
2. **Массовые операции с товарами** (мета-теги, редиректы, шаблоны страниц) — ручной труд или API. Планировать трудозатраты контент-менеджера клиента.
3. **`robots.txt` и `sitemap.xml`** — платформа даёт базовую генерацию, тонких настроек нет. Если понадобится, например, скрыть от индексации фильтрованные URL — решается через `meta robots` или JS.
4. **Redirect-план миграции URL** со старого сайта — обязательный артефакт перед запуском, вынесен в основной реестр как **ОВ16**.
5. **Никакой серверной логики** — все динамические функции только через клиентский JS или внешние сервисы (webhook + бэкенд клиента).
6. **API доступен только на Business+** — на старте не требуется (обосновано в разделе 14).
