## 1. Зачем этот документ

Собран отдельный план по этапу сборки сайта в Tilda, потому что этот этап определяет структуру будущего каталога и распределение работ между исполнителем и заказчиком. План опирается на результаты живого теста платформы, проведённого 20.08.2026, и заменяет предыдущие предположительные оценки на подтверждённые.

Документ фиксирует три вещи: что уже готово, в какой последовательности собирается каталог и что для этого нужно от заказчика. Отдельная docx-версия — в документах проекта, для архива и передачи.

---

## 2. Что установлено тестом

Тест проведён на бесплатном пробном тарифе Tilda Personal, длительность 14 дней. Импортированы 8 препаратов, созданы разделы каталога, проверены адреса, мета-теги, привязка товаров к разделам, вложенность.

### Что работает как надо

- Каждое значение справочника (культура, вредный объект, действующее вещество) получает собственную страницу в Tilda — 190 отдельных страниц вручную заводить не придётся, это административная операция внутри каталога.
- Адреса страниц могут быть человекочитаемыми, включая иерархию (например, `/gerbitsidi/pshenitsa`).
- Заголовок вкладки браузера (`<title>`) для каждой страницы раздела подставляется автоматически из названия раздела — базовое SEO обеспечено без ручной работы.
- Один препарат может одновременно относиться к нескольким разделам (тип, культура, объект, ДВ) без дублирования карточки. Адрес карточки всегда один и тот же, canonical единственный.
- Хлебные крошки строятся автоматически по иерархии разделов.
- Адреса товаров задаются через CSV-импорт — все 87 карточек получают человекочитаемые URL за один импорт.

### Что требует ручной работы или обходного пути

- Мета-описание раздела (`description` для поисковиков) стандартных полей не имеет. Для приоритетных 30–50 значений понадобятся отдельные «специальные страницы разделов» — они позволяют полностью управлять мета-тегами и содержимым.
- Slug (адрес) раздела в CSV не задаётся — правится в интерфейсе платформы. Для 190 разделов ~30 секунд на каждый — итого ~100 минут разовой работы.
- Иерархия URL (`/gerbitsidi/pshenitsa`) задаётся вручную, автоматически из иерархии разделов не наследуется.
- Фотографии по внешним URL с satom.ru не подгружаются — платформа satom блокирует скачивание с чужих IP. Фото загружаются в CDN Tilda предварительно (у нас есть локальные файлы из `parsed_v2/`).

## 4. Пошаговый план сборки

Порядок оптимизирован так, чтобы независимые куски работы можно было делать параллельно (например, шаги 3 и 6), а зависимые шли строго последовательно.

### Шаг 1. Оплата аккаунта Tilda клиентом

- **От заказчика:** оплатить тариф Personal (~750 ₽/мес) или Business (~1250 ₽/мес). Разница — Business позволяет вести до 5 сайтов и даёт доступ к API. Для одного сайта хватает Personal, но при желании готовить обновления через скрипт лучше Business. Рекомендую Business на первый год.
- **От исполнителя:** после оплаты — передать сайт с trial-аккаунта на аккаунт клиента через штатную функцию (Настройки сайта → Действия → Передать сайт). Занимает 5 минут.

### Шаг 2. Создание разделов каталога (190 значений)

Заводим в интерфейсе Tilda все три словаря: 52 культуры, 68 вредных объектов, 64 действующих вещества, плюс 7 категорий типов препаратов. Для каждого раздела указываем: название, slug (адрес), иерархию (родительский раздел).

Работа механическая, но требующая внимания к транслитерации адресов. Slug'и уже сгенерированы в словарях — просто вводим готовые.

**Трудозатраты:** ~30 секунд на раздел × 190 = ~100 минут = **1,5–2 часа**.

### Шаг 3. Загрузка фотографий в CDN Tilda

117 уникальных фотографий упаковок из локальных файлов `parsed_v2/photos/`. Массово через веб-интерфейс: перетаскивание в модуль медиа.

На этом же шаге собираем таблицу «имя товара → URL фото в Tilda CDN» — понадобится для CSV-импорта на следующем шаге.

**Трудозатраты:** **1,5–2 часа**.

### Шаг 4. Генерация боевого CSV на 87 SKU

Скрипт из готовых маппингов собирает многострочный CSV. Каждый товар — несколько строк с одинаковым `External ID` и разными значениями `Category` (по одной строке на каждый раздел, к которому товар относится). Всего ~700 строк.

Столбцы: `Brand`, `SKU`, `External ID`, `Category`, `Title`, `Description`, `Text`, `Photo` (URL из Tilda CDN), `Price`, `URL` (человекочитаемый адрес карточки), `SEO title`, `SEO descr`.

**Трудозатраты:** 1 час на скрипт + 30 минут на ревью и правки = **1,5 часа**.

### Шаг 5. Импорт CSV в Tilda

Через штатный импорт (Товары → Ещё → Импортировать из CSV). Проверяем сопоставление колонок (наши английские заголовки совпадают со штатными автоматически).

После импорта все 87 карточек привязаны к нужным разделам, у каждой человекочитаемый URL, у каждого раздела — товары.

**Трудозатраты:** **30 минут** (сам импорт быстрый; время на проверку выборочных карточек).

### Шаг 6. Настройка шаблона карточки товара

В Tilda один шаблон карточки на весь каталог. Собираем его в Zero Block по принятому макету пилотной Балерины. Все 87 карточек будут выводиться через этот шаблон, отличаясь только данными.

В шаблон входят: галерея фото, блок «Против объектов», регламент применения (таблица), «Первая помощь» (полностью), состав, аналоги, кросс-селл, кнопка заявки.

**Трудозатраты:** **8–12 часов** (это уже вёрстка, а не админка каталога).

### Шаг 7. Настройка шаблона листинга и главной каталога

Листинг категории (пример — гербициды): собираем по принятому макету v22. Здесь используются стандартные блоки Tilda с настроенными фильтрами.

Главная страница каталога — упрощённая, с крупными плитками категорий и переходом в четыре параллельных входа (по типу, по культуре, по объекту, по ДВ).

**Трудозатраты:** **6–8 часов**.
