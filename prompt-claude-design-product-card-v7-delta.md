# Дельта-промпт: карточка Балерина v7

**Базовый файл:** `phase-3-design/3.3-mockups/Product_card_balerina.dc.html` (v6, SHA `6b510b6b4ce6f226148095ced895d0e04e1bb0be`)
**Тип изменения:** правки в модалке заявки (шаг 1 и шаг 5) + добавление реактивного состояния согласия ПД
**Дата:** 21.08.2026
**Основание:** ТЗ на систему форм захвата заявок `phase-5-tilda/forms-specification.md` (§4 шаг 1, §4 шаг 5, §6). Приведение модалки в соответствие с решениями ДЗ07 (согласие ПД с указанием цели, без предустановленной галочки) и НР13 (единый клиентский путь без сегментации — добавление опции «Другое» на первом шаге, чтобы физлицо не отсекалось от формы).

Дизайн модалки, её структуру, стилистику, стили кнопок, порядок шагов и всё остальное содержимое карточки **не трогаем**.

## Изменение 1: Шаг 1 модалки — добавить пятую опцию «Другое»

В data section, в массиве `CLIENT_TYPES`, добавить пятый элемент:

**Было:**
```javascript
const CLIENT_TYPES = ["Юрлицо", "ИП", "КФХ", "Самозанятый"];
```

**Стало:**
```javascript
const CLIENT_TYPES = ["Юрлицо", "ИП", "КФХ", "Самозанятый", "Другое"];
```

Никаких других правок на шаге 1 не требуется — chip-кнопки рендерятся циклом по массиву, новый вариант появится автоматически с тем же стилем.

## Изменение 2: Шаг 5 модалки — новая формулировка чекбокса согласия

**Было** (внутри `sc-if value="{{ step5 }}"`, блок `<label>`):
```html
<label style="display:flex; gap:10px; align-items:flex-start; margin-top:18px; font-size:14px; line-height:1.5; color:#6B7280;">
  <input type="checkbox" style="margin-top:3px;">
  <span>Согласен на обработку персональных данных в соответствии с <a href="/privacy-policy/">политикой</a></span>
</label>
```

**Стало:**
```html
<label style="display:flex; gap:10px; align-items:flex-start; margin-top:18px; font-size:14px; line-height:1.5; color:#6B7280;">
  <input type="checkbox" onChange="{{ toggleConsent }}" checked="{{ consent }}" style="margin-top:3px;">
  <span>Даю согласие на обработку персональных данных для обработки заявки и подготовки коммерческого предложения. Ознакомлен с <a href="/privacy-policy/" target="_blank" rel="noopener noreferrer">Политикой обработки персональных данных</a>.</span>
</label>
```

Три содержательных отличия в разметке:
1. Формулировка текста — по §4/§6 ТЗ форм. Содержит цель обработки и полную ссылку на политику.
2. У ссылки на политику — `target="_blank" rel="noopener noreferrer"`. Клиент не должен терять заполненную форму при клике на политику.
3. У `<input>` — атрибуты `onChange` и `checked` привязаны к реактивному состоянию `consent` (см. изменение 3). Начальное значение `consent = false`, значит атрибут `checked` не активен по умолчанию — что соответствует требованию ДЗ07 (нет предустановленного согласия).

## Изменение 3: Реактивное состояние `consent` и блокировка кнопки «Отправить заявку»

В классе `Component`:

**3.1. В начальном `state` добавить поле `consent`:**

**Было:**
```javascript
state = {
  w: typeof window !== "undefined" ? window.innerWidth : 1440,
  open: {}, showTop: false, modalOpen: false, step: 0, clientType: "", side: "front",
  zoom: false, zoomPos: "50% 50%", lightboxOpen: false, lbZoom: false
};
```

**Стало:**
```javascript
state = {
  w: typeof window !== "undefined" ? window.innerWidth : 1440,
  open: {}, showTop: false, modalOpen: false, step: 0, clientType: "", side: "front",
  zoom: false, zoomPos: "50% 50%", lightboxOpen: false, lbZoom: false,
  consent: false
};
```

**3.2. В `openModal` — сбрасывать `consent` при каждом открытии модалки:**

**Было:**
```javascript
openModal: () => this.setState({ modalOpen: true, step: 0 }),
```

**Стало:**
```javascript
openModal: () => this.setState({ modalOpen: true, step: 0, consent: false }),
```

**3.3. В `renderVals` — добавить обработчик `toggleConsent`, флаг `consent` (для привязки к `checked` в разметке чекбокса) и вычисляемые `nextDisabled` + стиль кнопки «Отправить заявку»:**

Логика:
- На шагах 0–3 кнопка «Далее» всегда активна (валидация полей — задача Tilda в бою, в макете не эмулируется).
- На шаге 4 (это `step === 4`, соответствует шагу 5 в UI, «Подтверждение») кнопка «Отправить заявку» активна только если `consent === true`.
- Визуально disabled-состояние: приглушённый фон `rgba(228,168,83,0.45)`, курсор `not-allowed`.

Добавить в объект, возвращаемый `renderVals`, три поля:

```javascript
consent: this.state.consent,
toggleConsent: () => this.setState(s => ({ consent: !s.consent })),
nextButtonStyle: (step === 4 && !this.state.consent)
  ? "margin-left:auto; background:rgba(228,168,83,0.45); color:#26543E; border:none; border-radius:4px; padding:14px 28px; font-size:16px; font-weight:700; cursor:not-allowed;"
  : "margin-left:auto; background:#E4A853; color:#26543E; border:none; border-radius:4px; padding:14px 28px; font-size:16px; font-weight:700; cursor:pointer;",
nextStep: () => {
  if (this.state.step === 4 && !this.state.consent) return;
  this.setState(s => ({ step: Math.min(s.step + 1, 5) }));
},
```

Существующее поле `nextStep` в возвращаемом объекте заменяется на вариант выше (с гвардом по consent на шаге 4). Существующее поле `prevStep` остаётся без изменений.

**3.4. В разметке кнопки «Отправить заявку» / «Далее» — использовать `nextButtonStyle` вместо статичной строки:**

**Было:**
```html
<button onClick="{{ nextStep }}" style="margin-left:auto; background:#E4A853; color:#26543E; border:none; border-radius:4px; padding:14px 28px; font-size:16px; font-weight:700; cursor:pointer;">{{ nextLabel }}</button>
```

**Стало:**
```html
<button onClick="{{ nextStep }}" style="{{ nextButtonStyle }}">{{ nextLabel }}</button>
```

Иных правок кнопки нет.

## Изменение 4: Экран «Готово» — уточнение формулировки

Формулировка на экране «Готово» (шаг 6, `stepDone`) в текущем макете и в ТЗ (§4) совпадают по смыслу, но в макете идут два `<p>`, а в ТЗ — три строки с явным жирным акцентом на «Заявка принята» и номере телефона.

**Было:**
```html
<sc-if value="{{ stepDone }}" hint-placeholder-val="{{ false }}">
  <div>
    <p style="margin:0 0 14px; font-size:16px; line-height:1.6; color:#1A1D1F;">Заявка принята. Специалист свяжется в рабочее время — Пн–Чт 9:00–17:00, Пт 9:00–16:00.</p>
    <p style="margin:0; font-size:16px; color:#6B7280;">Срочный вопрос — <a href="tel:+73517500920" style="font-weight:700;">+7 (351) 750-09-20</a></p>
  </div>
</sc-if>
```

**Стало:**
```html
<sc-if value="{{ stepDone }}" hint-placeholder-val="{{ false }}">
  <div>
    <p style="margin:0 0 14px; font-size:18px; font-weight:700; color:#1A1D1F;">Заявка принята.</p>
    <p style="margin:0 0 14px; font-size:16px; line-height:1.6; color:#1A1D1F;">Свяжемся в рабочее время: Пн–Чт 9:00–17:00, Пт 9:00–16:00.</p>
    <p style="margin:0; font-size:16px; color:#6B7280;">Срочный вопрос — <a href="tel:+73517500920" style="font-weight:700;">+7 (351) 750-09-20</a></p>
  </div>
</sc-if>
```

Разбивка «Заявка принята.» отдельной строкой с жирным акцентом делает исход заявки визуально считываемым за 0,5 секунды.

## Обоснование (зафиксировано, не в промпт Claude Design)

- **Опция «Другое» на шаге 1** — устраняет ситуацию, когда физлицо (не юрлицо, не ИП, не КФХ, не самозанятый) не находит подходящей опции и бросает форму. Соответствует НР13 (единый клиентский путь без сегментации).
- **Формулировка чекбокса** — прямое требование ДЗ07 (152-ФЗ ст. 9 в ред. 156-ФЗ от 24.06.2025): согласие оформляется отдельно от иных условий и с явно указанной целью обработки. Штрафы РКН до 700 тыс. руб.
- **`target="_blank"` для ссылки на политику** — заполненная форма не должна теряться при переходе на политику.
- **Динамическая привязка `checked` к `consent = false`** — обеспечивает отсутствие атрибута `checked` в отрендеренной разметке, что при автоматизированном мониторинге РКН квалифицируется как «нет предустановленного согласия» (соответствие правилу).
- **Блокировка кнопки** — техническое подкрепление правила «нельзя отправить форму без явного согласия».
