# CLAUDE.md — сайт ООО «Восток АгроХим»

## Начало каждой сессии
1. Прочитай `00-management/status.md` из репозитория до первого содержательного ответа.
2. Сообщи: «прочла status.md, активная задача X, отменены Y и Z».
3. Если status.md противоречит твоей памяти или другим файлам — прав status.md.
4. Одна сессия — одна логическая задача. В конце — готовый стартовый промт для следующей.

## Что строим
Статичный сайт без платформы-конструктора (НР18). Данные → шаблоны Jinja2 → HTML в `dist/` → автовыкладка на российский хостинг. План: `00-management/work-plan-selfbuilt-v1.md`. Адреса, перечень страниц, схема данных: `00-management/site-structure-v1.md`. Решения: `00-management/decisions-registry.md`. Не вводи страницы и функции, которых нет в реестре и плане; при сомнении спроси.

## Структура репозитория
- Новое (самописный сайт): `data/`, `content/`, `assets/`, `site/` (шаблоны), `scripts/` (генератор и проверки), `dist/` (результат сборки, не в git), `design-reference/` (макеты, не в git).
- Старое: папки `phase-*` и файлы в корне — история и исходные материалы. `phase-5-tilda/*` — исторические (НР16); переиспользуется только переносимое содержимое (CSV-логика, список разделов, HTML вкладок).

## Эталон вида
Согласованные макеты лежат в `design-reference/` (вне git): главная, листинг гербицидов, карточка Балерины, десктоп и мобильная версия. Теги `sc-for`, `sc-if`, `style-hover` — формат Claude Design, не HTML: hover/focus переписывай в CSS. Макеты — эталон; расхождение с ним считается ошибкой.

## Данные
- `data/products.csv` — каталог (строка = SKU); `data/prices.csv` — цены; `data/settings.yml` — телефоны, график, реквизиты. Два последних правит заказчик, не меняй их структуру.
- Цены попадают в страницы только при сборке из `prices.csv`. Не вписывай цену в шаблон и не подставляй в браузере.
- Источники: юридически значимые поля (класс опасности, срок хранения, регистрация) — agroxxi.ru приоритетнее satom (ПИ10); упаковки и срок хранения — каталог Августа.
- Не публикуем: регномер, дату свидетельства, класс ДОПОГ. В карточке ровно 7 характеристик: действующее вещество, форма препарата, тип применения, способ проникновения, класс опасности для человека, класс опасности для пчёл, фитотоксичность.
- Исключённые SKU: У02–У06.

## Контент и тексты
- Название препарата — только при подтверждённой связке препарат → культура → объект. Если сомневаешься — не пиши, не ставь флаг.
- Без конкретных чисел (нормы, фазы, дни, температуры), кроме проверенных ЭПВ. Без FRAC/IRAC/HRAC.
- Не более 2–3 препаратов на функциональную группу. Прилагательное перед существительным («яровая пшеница»). «Синтетические ауксины», не «гормональные гербициды».
- Правила SEO-текстов — в шапках `phase-4-content/wave-*-seo-texts.md`.
- Не использовать: «прямые дистрибьюторы», «Гарантия производителя на всю реализуемую продукцию» (формулировка по ДЗ10), стоп-слова ДЗ04, индикаторы наличия (ПИ11), оптовые шкалы скидок (НР02).
- Не создавать и не упоминать: /opt, /oferta/, /dacha (НР01, НР13, НР14), Щёлково (НР05), логотипы вторичных производителей (НР04), Telegram-бот (НР12).
- Десиканты — седьмая категория `/catalog/desikanty/`; препарат физически лежит в гербицидах, страница строится по тегу `desikaciya` (ПИ08, catalog-ia v1.7).

## Заявки и персональные данные

## Безопасность
- Не коммить секреты, ключи, пароли, персональные данные, журналы заявок. Секреты — в хранилище GitHub и на хостинге.
- Изображения: каждый файл с alt и записью в журнале источников (ДЗ09).

## Работа с репозиторием
- Перед коммитом запускай `make check` (он сам запускает сборку) и `make test` (самопроверка проверок). Если проверки падают — не выкладывай, объясни причину.
- Ветка `main` выкладывается на боевой сайт, `staging` — на закрытую тестовую копию. Правки сначала в `staging`.
- Коммиты на русском, одна логическая правка = один коммит. Решения фиксируй в `decisions-registry.md` до или сразу после согласования.
- Каждый этап плана начинается после согласования результата предыдущего.
