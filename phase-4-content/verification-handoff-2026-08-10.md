## Как fetchить (шаблон URL)

agroxxi.ru использует стандартную схему: `https://www.agroxxi.ru/goshandbook/prep/{transliterated-name}-{form}-{version}.html`

Примеры проверенных URL (10.08.2026):
- `tabu-vsk-3.html` — Табу

## Правила нормализации satom/agroxxi → словарь

### Культуры (C-коды)

Все действующие C-коды — в `dictionary-crops-v1.md` v1.1. Ключевые правила:

- **Пшеница** = C001 (общее). Если agroxxi разделяет: **пшеница озимая** = C002, **пшеница яровая** = C003.
- **Ячмень** = C004 (общее). **Ячмень озимый** = C005, **ячмень яровой** = C006.
- **Рожь** = C007 (общее), **рожь озимая** = C008.
- **Тритикале** = C010 (общее), **тритикале озимая** = C011.
- **Овёс** = C012 (не в иерархии).
- **Зерновые колосовые культуры (без уточнения)** — если agroxxi указывает эту формулировку, разметить как **C001 + C004 + C007 + C010** (пшеница + ячмень + рожь + тритикале, без овса).
- **Лён-долгунец** = C021, **лён масличный** = C022 (раздельно — ОВ24).
- **Свёкла сахарная** = C025, **свёкла кормовая** = C025a, **свёкла столовая** = C035.
- **Бахчевые** (арбуз/дыня/тыква/кабачок) — все под зонтичным C038a (ОВ27).
- **Плодово-ягодные, кроме яблони/груши, — НЕ РАЗМЕЧАТЬ** (ОВ26): смородина, клубника, вишня, слива, персик и т.п. → в описании продукта, не в фильтре.

### Вредные объекты (W/D/I-коды)

Все действующие коды — в `dictionary-pest-objects-v1.md`.

**Ключевые тождества:**
- **Оидиум** (для винограда) = **D008** отдельно, не сливать с D007 «Мучнистая роса» (там разные возбудители).
- **Милдью** (винограда) = **D012** отдельно от D011 «Пероноспороз».
- **Крестоцветные блошки** = **I008**, **хлебные блошки** = **I006**, все прочие = **I007** «Блошки» (зонтичный).
- **Головня** — все виды (твёрдая, пыльная, каменная, чёрная, стеблевая, ложная) сливаются в **D005**.
- **Ржавчина** — все виды (бурая, стеблевая, жёлтая) в **D006** (ОВ30).
- **Пятнистость** без уточнения = **D009** fallback (ОВ29). Конкретные пятнистости — D001/D002/D003/D010 по возбудителю.

**Обнаруженные пробелы словаря v1** (для протравителей):
- **Проволочники** (личинки жуков-щелкунов, Elateridae) — почвенные вредители всходов. В v1 нет. Флаг: `⚠️ проволочники — в описании продукта`.
- **Злаковые мухи** (шведская, гессенская и др.) — вредители всходов зерновых. В v1 нет. Флаг: `⚠️ злаковые мухи — в описании продукта`.
- **Пасмо льна** — специфическое заболевание. В v1 нет. Флаг: `⚠️ пасмо льна — в описании продукта`.

Если появятся **другие новые категории** (например, «плодожорка яблонная» для инсектицидов сада) — тоже флагом в описании, **не создавать I021/D021** без согласования с PM-сессией.

## Технические заметки по MCP GitHub

Из userMemories и опыта работы:

1. **SHA обновлять перед КАЖДЫМ апдейтом** — если делаешь два create_or_update_file подряд, между ними обязательно `get_file_contents` для свежего SHA. Стейл-SHA → 409 Conflict.

2. **str_replace на MCP GitHub нет** — только `create_or_update_file`. То есть каждое обновление требует **всей** новой версии файла. У обоих mapping-файлов есть основная таблица И приложение Б с сырыми данными — обновлять надо только основную таблицу.

3. **Дубль строк в таблице**: одна и та же П-код встречается в основной таблице И в приложении Б. При Python-скрипте использовать паттерн `re.search` для первого вхождения, **НЕ** `re.sub` без ограничения. Пример корректной замены:
   ```python
   pattern = re.compile(rf'^(\| \d+ \| {re.escape(p_code)} \| [^|]*\|)[^|]*\|[^|]*\|$', re.MULTILINE)
   m = pattern.search(text)
   # заменяем только m.group() на новую строку
   ```

4. **Файлы для скачивания** — через `raw.githubusercontent.com` (в whitelist для bash):
   - `https://raw.githubusercontent.com/viroman1972-jpg/vostok-agrohim-website/main/phase-4-content/product-crop-mapping-v1.md`
   - `https://raw.githubusercontent.com/viroman1972-jpg/vostok-agrohim-website/main/phase-4-content/product-pest-mapping-v1.md`
   - Для reference: `https://raw.githubusercontent.com/viroman1972-jpg/vostok-agrohim-website/main/phase-4-content/dictionary-crops-v1.md`
   - Для reference: `https://raw.githubusercontent.com/viroman1972-jpg/vostok-agrohim-website/main/phase-4-content/dictionary-pest-objects-v1.md`

5. **agroxxi.ru — в whitelist bash нет.** Для fetch использовать только MCP `web_fetch`.

6. **Экономия контекста.** Каждый fetch = 30–40 KB. Лимит одной сессии — **~5–6 SKU** до заметного роста контекста. Оптимально: два прохода — один для 8 SKU из пакета 1+2 (сначала загружаешь mapping-файлы, потом 8 fetch-ов, потом одна запись), второй проход для 8 остальных.

## Формат обновления таблицы разметки

Каждое обновление 1 SKU = замена одной строки в основной таблице. Формат:

```
| N | P-код | Название | C-коды через " · " | agroxxi 10.08.2026[; примечание] |
```

Флаг **обязательно** содержит «agroxxi 10.08.2026». Если появилось новое значение, не поддерживаемое v1 словарём, добавь **после точки с запятой** формулировку типа `пасмо льна — в описании продукта`.

## Что делать при неопределённостях

- **URL не найден в agroxxi:** web_search — обычно первая ссылка правильная.
- **Регистрация препарата истекла** (Ректор — П68): не размечать, пометить «⚠️ регистрация истекла».
- **Товар №92 Лямбда-С (П91)**: не размечать, если Прутян не прояснил (см. ОВ14).
- **Новая категория культур/вредных объектов, не в v1 словаря:** флагом в колонке «Флаги», без изменения словаря. Финальное решение о расширении v1.2 — за PM-сессией.
- **Пропуск SKU** (например, agroxxi недоступен весь пакет): пометь `⚠️ agroxxi недоступен` во флаге, продолжай следующий.
