## 2. Архитектура

### 2.1. Из чего и чем собираются страницы

- **Генератор на Python + Jinja2** → статичные HTML/CSS и немного JS (мегаменю, модальная форма, cookie-баннер, фильтры и сортировка листинга, поиск). Причина: парс parsed_v2 и скрипты проекта (`scripts/`) уже на Python; один язык. *Подтвердить (О2).*
- **Эталон вида:** согласованные макеты (главная, листинг гербицидов, карточка Балерины; десктоп и мобильная версия). Макеты сделаны в формате Claude Design (теги `sc-for`, `sc-if`, атрибуты `style-hover`) — это не готовый HTML: при переносе hover/focus переписываются в CSS, данные берутся из таблицы. Входит в трудозатраты этапа 3.
- **Данные:** по таблице каталога, а не вручную в страницах (см. 2.2).
- **Шрифты** Merriweather и Manrope подключаются в макете с Google Fonts → при сборке скачиваются и отдаются со своего сайта. *Рекомендация:* быстрее, нет передачи данных посетителя на внешний сервис (логика НР17). *Согласовать (О8).*

### 2.2. Где хранятся данные

Источник истины — репозиторий. Excel остаётся только исходником разового импорта (его нельзя править в веб-интерфейсе GitHub).

```
data/
  products.csv        — одна таблица каталога: строка = SKU (название, slug, категория, производитель,
                        форма, 7 характеристик, теги, флаг доставки, поля SEO)
  prices.csv          — slug;цена;единица;статус (published/archived)   ← правит заказчик
  settings.yml        — телефоны, график, реквизиты, e-mail, ссылки    ← правит заказчик
  dict/               — категории (7), культуры (52), вредные объекты (68), ДВ (64), серии
  links/              — препарат→культура, препарат→объект, препарат→ДВ, «Смотрите также» (ДМ29)
content/
  products/<slug>/    — длинные тексты карточки (вкладки: регламент, первая помощь, …)
  seo/                — SEO-тексты 3 волн для категорий, культур, объектов, ДВ
  pages/              — about, contacts, comments, privacy-policy
assets/               — фото упаковок, фото блоков; журнал источников изображений (ДЗ09)
```

7 полей характеристик (решение Прутяна А.В. 24.08.2026): действующее вещество, форма препарата, тип применения, способ проникновения, класс опасности для человека, класс опасности для пчёл, фитотоксичность. Регномер, дата свидетельства, класс ДОПОГ не публикуются.

### 2.3. Решение по ценам

**Рекомендация: цены лежат в отдельном файле `prices.csv` и подставляются в страницы при сборке** (не в браузере посетителя и не вручную в коде страницы).

- Цена попадает в готовый HTML карточки, листингов, блока «Смотрите также» и в разметку товара для поиска (`Offer`) — из одного места, расхождений нет.
- Правка цены = одна строка в одном файле; страницы пересобираются автоматически. Разработчик не нужен.
- Подстановка в браузере хуже: поисковик может не увидеть цену в разметке, страница мигает при загрузке.
- Цены в коде страниц хуже: одна правка требует найти карточку, листинги, кросс-блоки и разметку — риск расхождений.
- Автопроверка: у каждой опубликованной карточки есть цена (П10); цена в видимом тексте и в разметке совпадает.

### 2.4. Адреса, хостинг, SSL, домен

- **Адреса** — по `catalog-ia` §7: `/catalog/{категория}/{товар}/`, `/catalog/kultura/{}`, `/catalog/vrednyy-obekt/{sornyaki|vrediteli|bolezni}/` и `/{объект}/` (ДМ26), `/catalog/dv/{}`, `/catalog/seriya/{}` (только серии ≥2 препаратов, ПИ06), `/catalog/gerbitsidy/promyshlennye/` (ДМ31), `/catalog/all/`. «Десиканты» — представление по тегу (ПИ08, уточнение 09.08.2026). Все ~190 значений словарей получают страницы (ОВ36); для приоритетных 30–50 — SEO-текст (`phase-5-tilda/priority-sections-list.md`).
- **Перечень служебных страниц** строится по реестру: `/about/` (футер, ДМ34), `/comments/` (П06), `/contacts/`, `/privacy-policy/` (ДЗ01), `/sitemap/` (ДМ19), 404, файл прайса (П07). Страницы `/opt`, `/oferta/` не создаются (НР13, НР14), `/dacha` — НР01. Документ `sitemap-and-navigation.md` содержит устаревшие страницы (`/opt`, `/dacha`, `/legal/*`, `/delivery`, `/warranty`, `/documents`, `/faq`) — перед этапом 3 свести перечень с реестром (задача этапа 1). Отдельные страницы «Согласие», «Пользовательское соглашение», «Cookies» не создаются (НР19): согласие — галочка в форме, cookie — раздел Политики ПДн.
- **Хостинг в РФ.** Критерии отбора (сравнить 2–3 предложения на этапе 0, цены не называю — не проверял): доступ SFTP/SSH для автовыкладки; поддержка 301-редиректов (`.htaccess` или аналог) — для ОВ16; PHP для скрипта заявок; почта домена и управление DNS (SPF/DKIM); бесплатный SSL с автопродлением; оформление на ООО «Восток АгроХим».
- **Домен** `vostok-agrohim.ru` — оформлен на ООО; доступ у заказчика (К1).
- **Тестовая копия:** ветка `staging` выкладывается на закрытый паролем поддомен, закрытый от индексации. Используется для приёмки и обучения заказчика.

### 2.5. Выкладка, секреты, резерв

- При изменении в ветке `main` автоматически: сборка → автопроверки → при успехе выкладка на хостинг. При провале проверок сайт остаётся прежним, приходит письмо с причиной.
- Каждая успешная сборка сохраняет архив готового сайта (резервная копия).
- **Секреты:** ключ выкладки — в хранилище секретов GitHub; пароль почты скрипта заявок — только на хостинге вне репозитория. Репозиторий приватный; персональные данные (заявки, журнал согласий) в репозиторий не попадают — хранятся на хостинге в РФ.
- Откат: кнопка отмены правки в GitHub; если GitHub недоступен — локальная сборка у Оли и ручная загрузка.

### 2.6. Приём заявок (ДМ35, НР17, ДЗ07)

- Обычная короткая форма в модальном окне (одна форма, точки вызова и контексты «Товар / Категория / Общий» — по `phase-5-tilda/forms-specification.md`, упрощённо по ДМ35).
- Небольшой серверный скрипт на хостинге: проверка полей; **отказ, если нет галочки согласия** (проверка на сервере, а не только в браузере); скрытое поле-ловушка и ограничение частоты (ДМ35 п.6); журнал «дата, время, IP, состояние галочки» (ДЗ07 п.5) на хостинге; письмо на `vostokxim@mail.ru`.
- Письмо отправляется от имени домена: SPF, DKIM, DMARC в DNS; в «Ответить» — адрес из формы. Проверка доставки в ящик mail.ru (не в спам).
- Если отправка не удалась — посетитель видит телефон, а не «успех» (заявка не теряется молча). После успеха: «Если не ответим в течение рабочего дня, позвоните» + телефон (ДМ35 п.5).
- Google Sheet и зарубежные сервисы — нет (НР17). Уведомления в Telegram/MAX на старте не делаем (необязательны по ДМ35 п.3, платформа «штатно» их больше не даёт; вернуться — после запуска). *Согласовать (О8).*

### Этап 10. Администрирование и сопровождение (9–13 ч)

**Требование заказчика (К4, 22.10.2026):** заказчик сам меняет цены; бывает, что производитель меняет цены внезапно, поэтому срочная правка цены должна доходить до боевого сайта за минуты, без ожидания Оли. Как правка `prices.csv` попадает на боевой сайт в обход правила «сначала `staging`» (например, правка цен сразу в `main` с теми же проверками) — решить и согласовать с Олей на этапе 10.

**Инструкция для заказчика (1–2 страницы, печатная):**
- что где лежит: два файла — `prices.csv` и `settings.yml` — и загрузка файла прайса;
- как поменять цену; как поменять телефон/график; как снять препарат (статус `archived`); как заменить прайс-лист — по шагам со снимками экрана;
- как убедиться, что правка прошла (зелёная галочка в списке изменений; страница обновляется через несколько минут);
- красный крест: что значит, как отменить правку одной кнопкой, кому позвонить;
- что делать, если сайт или заявки не работают: чек-лист (открывается ли сайт, приходят ли письма, тестовая отправка формы раз в месяц), телефоны Оли и поддержки хостинга;
- чего не трогать: все папки, кроме `data/`, названия адресов (slug), столбцы таблицы.

**Инструкция для Оли:** карта репозитория; как начинать сессию в Claude Code (чтение `status.md`, `CLAUDE.md`); как добавить препарат / новую страницу значения словаря; запуск сборки и проверок; выкладка и откат; секреты и их замена; ежегодные и периодические задачи (ОВ40 — новое дилерское письмо после заключения договора на год; обновление Политики при изменении закона, новом счётчике; журнал изображений; согласия авторов новых отзывов); разбор сбоев (проверки упали, выкладка не прошла, заявки не доходят, домен/SSL).

**Проверка на заказчике:** на тестовой копии (ветка `staging`) заказчик выполняет без помощи 4 задачи (цена, телефон, снятие препарата, замена прайса) и одну заведомо ошибочную правку, чтобы увидеть красный крест и сделать откат. Время заказчика 1–2 ч. Критерий: справился сам; что вызвало вопросы — переписывается в инструкции.

**Запасной вариант:**
- распечатанная инструкция и лист с доступами (хостинг, домен, GitHub, почта) — у заказчика, не в репозитории и не в чате;
- архив готового сайта после каждой выкладки + ежеквартальная копия на диск заказчика (персональных данных в нём нет);
- обычные правки не требуют Claude (таблица → автосборка); Claude нужен для изменения структуры;
- если GitHub недоступен: Оля собирает локально и загружает вручную; в крайнем случае — правка телефона/цены в готовых файлах через файловый менеджер хостинга, после чего та же правка обязательно вносится в таблицу (иначе следующая сборка её затрёт);
- доступ заказчика: бесплатная учётная запись GitHub, приглашение в приватный репозиторий с правом записи, двухэтапный вход (О4).
