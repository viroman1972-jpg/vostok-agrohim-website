# Инвентаризация страниц сайта

**Проект:** редизайн сайта ООО «Восток АгроХим»
**Дата:** 17.08.2026
**Назначение:** единый список всех страниц нового сайта — что должно существовать к запуску, откуда берётся контент, что уже решено, а что придумано только в макете.

**Зачем документ:** дыры вскрывались поштучно и случайно — сначала «Полезное» (раздел без содержимого, У07), затем «Оптовым покупателям» (ссылка на несуществующую страницу). Причина одна: ссылки в макетах появлялись раньше решений о страницах. Этот документ закрывает разрыв.

**Источники:** `catalog-ia-v1.md` v1.7 §7 (схема URL), макеты `Hero.dc.html` / `catalog-listing-gerbicidy.dc.html` / `Product_card_balerina.dc.html` (фактические ссылки), `00-management/decisions-registry.md` (решения).

## 4. Три страницы без решения

### 4.1 `/opt` — «Оптовым покупателям»

**Что не так:** ссылка стоит в футере всех трёх макетов, но страницы нет ни в URL-схеме IA, ни в структуре главной. В реестре ДМ08 сформулирован как «короткий блок „специальные условия для опта" без публичных цен» — то есть предполагался *блок на главной*, а не отдельная страница. Блока на главной тоже нет: тема опта присутствует единственной строкой внутри блока «Знаем продукт. Понимаем задачи хозяйства» (ДМ13) — «Отпустим и одну упаковку, и оптовую партию».

**Почему стоит делать страницу, а не убирать ссылку:** в отличие от «Полезного», контент здесь уже существует в решениях, писать с нуля и привлекать агронома не требуется:

| Что вошло | Решение |
|---|---|
| Специальные условия для опта, без публикации шкалы скидок | ДМ08 + НР02 |
| Работа по договору | ДМ07 |
| Оплата для физлиц: наличные при самовывозе или QR-код; эквайринга нет | ДМ12 + НР03 |
| Перечень отгрузочных документов **не публикуется**, условия в договоре | НР07 |
| Форма заявки с типом клиента (ЮЛ / ИП / КФХ / самозанятый) | ДМ03, ДМ30 |
| Типы клиентов и сценарии | ДМ05 |

Страница закрывает три ДМ (07, 08, 12), которые числятся принятыми, но нигде не реализованы, и даёт посадочную под коммерческие запросы вида «купить СЗР оптом Челябинск».

**Рекомендация:** создать страницу `/opt/`, объединив ДМ07 + ДМ08 + ДМ12. Отдельный структурный документ не нужен — страница короткая, достаточно раздела в промпте для Claude Design.

### 4.2 `/about/` — «О компании»

**Что не так:** страница есть на старом сайте, но отдельного решения о переносе в реестре нет — она не попала ни в один П. Ссылка на неё жила в шапках листинга и карточки, а 17.08.2026 по ДМ34 переехала в футер главной.

**Контент:** старый сайт `/about/` + уже согласованные формулировки — ДМ13 (позиционирование, пять пунктов), ПИ02 (с 2011 года), ПИ01 (дилерский статус вместо «прямых дистрибьюторов»), ПИ07 (производители).

**Рекомендация:** оформить как перенос с изменением — контент старой страницы приводится в соответствие с принятыми формулировками. Риск: на старой странице возможны утверждения, нарушающие 38-ФЗ (как ПИ01) — нужна вычитка.

### 4.3 `/return-policy/` — «Условия возврата и обмена»

**Что не так:** ссылка стоит внизу карточки товара (аудит §2 п. 22 — перенос), решения в реестре нет.

**Контент:** страница есть на старом сайте, переносится. Формально нужна по ЗоЗПП.

**Рекомендация:** оформить переносом (П), при вычитке сверить с действующей редакцией ЗоЗПП — на витрине без онлайн-оплаты (НР03, У01) формулировки про дистанционную продажу могут не подходить.

## 5. Ключевой риск: объём параллельных входов в Tilda

**Проблема.** По ДМ02 и ДМ26 каждое значение словаря — отдельная страница с ЧПУ: `/catalog/kultura/pshenitsa/`, `/catalog/vrednyy-obekt/septorioz/`, `/catalog/dv/glifosat/`. При словарях в несколько десятков культур, до двух сотен вредных объектов и несколько десятков ДВ это **от 190 до 310 страниц**, каждую из которых в Tilda нужно создать и настроить руками — динамической генерации ЧПУ-страниц по значению справочника платформа не даёт (`tilda-constraints.md`).

Это больше, чем все остальные страницы сайта вместе взятые, включая 87 карточек.

**Варианты решения:**

**а) ЧПУ только для приоритетных значений, остальное — через параметры фильтра.** Создаём вручную страницы для топ-значений, которые реально дают трафик (условно: 15 культур, 20 вредных объектов, 15 ДВ ≈ 50 страниц), остальные значения доступны через фильтр листинга с URL-параметром (`/catalog/gerbitsidy/?kultura=proso`). Хвост словаря не теряется — он ищется фильтром, просто без собственной посадочной.

**б) Все ЧПУ-страницы вручную.** Полное SEO-покрытие, но 190–310 страниц ручной сборки и последующего сопровождения. При изменении ассортимента каждая требует проверки.

**в) Только hub-страницы.** Три hub по подтипу (ДМ26) + вход по культуре, без страниц конкретных объектов и ДВ. Минимум работы, но теряется основная SEO-ценность входов — запросы «чем обработать пшеницу от септориоза» ведут именно на страницы конкретных объектов.

**Рекомендация: вариант (а).** SEO-ценность распределена крайне неравномерно — «пшеница» и «глифосат» дают несопоставимо больше трафика, чем «сорго» или «фенмедифам». Приоритетный список формируется по частотности запросов и по объёму ассортимента под значение; при накоплении статистики список расширяется.

**Предлагается завести ОВ36** — «Объём ЧПУ-страниц параллельных входов». Решать до Phase 5, потому что от него напрямую зависит трудоёмкость сборки.
